# Watchdog Energy Management 4.2.1

## Meter counter protection

- A successful Modbus reply containing a lower cumulative reading, including zero after a previously positive reading, no longer replaces the accepted kWh or volume total.
- The meter shows Counter Review and retains the last accepted reading and timestamp. The suspect reading is saved for review rather than as a normal reading.
- Other meter channels continue polling. Normal polling resumes for the affected meter when its counter reaches or exceeds the accepted total.
- Communication failures continue to preserve the last accepted readings.

A genuine controller counter reset or rollover requires investigation; this release does not reconcile a new counter baseline automatically. Previously overwritten readings are not repaired automatically.

## Validation and limitations

Regression tests cover disconnects, zero and lower replies, register mapping, repeated suspect replies, and recovery. The Linux test run passed 72 of 73 tests; the existing invoice PDF test fails because its font resolver requires Windows Arial fonts.

Delayed Modbus RTU responses remain under investigation. RTU read replies do not include the requested register address, so a valid late reply can resemble another channel's reply. This release does not claim to eliminate that issue; validation with the physical serial bus is still required.

## Windows upgrade

Back up the database using the application's backup interface before upgrading. The existing installer retains the application and customer-data paths. A packaged installer must be built with Inno Setup on Windows using installer/WatchDogEM.iss and the self-contained output in outputs/Watch-Dog-EM-win-x64. Test service restart and meter polling on Windows before distributing the installer.
