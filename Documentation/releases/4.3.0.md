# Watchdog Energy Management 4.3.0

## Billing integrity

- One shared billing run is used by the automatic monthly schedule, manual billing and the new preview, so all three follow the same rules.
- Suspect readings (a counter that went down) are never billed. A reading that dropped and then recovered by itself is treated as a communication glitch and ignored automatically.
- A billing period can only be generated after it has finished. Previously, billing the current month early lost the remaining days for good.
- Overlapping billing periods are refused, so no day can be billed twice.
- The period and all its invoices are saved in one transaction: either everything is created or nothing is.
- If any meter is not ready (no reading, counter review, no tariff), the automatic run publishes nothing, **keeps the month pending** and retries every hour. The reason is shown on the Operations page. Previously the month was skipped and its consumption was never billed.
- After a server shutdown, missed months are caught up one by one.
- Tariffs: a period is priced with the tariff in force at its end. A price changed after the period ended (for example on the 1st, before publication) no longer reprices the previous month.
- Unpaid balances are carried forward per meter **and shop**. A meter moved to another shop no longer passes the previous tenant's arrears to the new one.
- Draft invoices no longer count as money owed.
- Invoice numbers are never reused, even after invoices are deleted.

## Billing cycle start day

- Settings now choose the day the billing cycle starts (1–28) and how many days after the period end invoices are published (0–7). Example: start day 25 bills the 25th to the 24th of the next month.
- Existing schedules are converted automatically and keep the same publication dates (calendar month, published on the same day as before).

## Counter review and meter replacement

- New page **Meter → Counter review / meter replaced** (Administrators): *Ignore reading* for a glitch, or *Accept new starting value* after a real reset/replacement. Consumption is then billed correctly across the reset.
- *Meter replaced* tells the system that the next value read starts a new counter.
- Changing a meter's register, data type, word order or scaling (Modbus) or its billing energy point (BACnet) starts a new counter automatically, so the change is not billed as a jump.
- Previously a BACnet counter review could never be cleared and blocked billing permanently.

## Testing without waiting a month

- **Operations → Test billing (preview)** shows exactly which invoices a run would publish (readings, consumption, tariff, previous balance, totals, and anything blocking it) for any date or period. Nothing is saved or sent.
- On a test installation only (environment `Development`), the setting `Testing:ClockOffsetDays` moves the application clock forward so the real monthly run, publication and email can be watched end to end. A red warning is shown on the Operations page while it is active. Never use it on a live installation.
- 25 new automated tests drive the monthly schedule with a simulated clock (failure and retry, catch-up of missed months, mid-month cycles, February, year end).

## Security

- Every page now requires sign-in, including the dashboard and meter pages, which were visible to anyone on the network. A wall display can use a Viewer account with "Remember me".
- Until the first Administrator exists, registration and administrator setup are only accepted from the server computer itself (http://localhost:5080).
- Readings CSV export escapes values and neutralises spreadsheet formulas.

## Reliability

- Restore keeps a copy of the current database first (`watch-dog-em-before-restore-…db`) and upgrades an older backup to the current structure immediately.
- Meter polling no longer writes results read before a restore into the restored database.
- Permanently deleting a meter keeps its audit trail and records which invoices were deleted.
- Stopping the service no longer logs critical "BackgroundService failed" errors.

## Upgrade

Back up the database before upgrading. The database is upgraded automatically on first start. After upgrading, check Operations → Tariffs & billing cycle and use Test billing to preview the next run.
